# 홈 (`#/`)

> `/impeccable shape`로 확정(2026-11-08). 제품 사실은 PRODUCT.md와 docs/brief.md, 시각 결정은 4단계 DESIGN.md가 기준이다.

## 범위와 모드

- **Read 모드**: 문서 입구다. 광고처럼 설득하지 않는다. 목표는 어느 가이드로 갈지 바로 고르기다.
- 배포 단위는 `index.html` 안의 해시 화면 `#/`다.

## 정보 우선순위

1. 가이드 입구(최종 워크플로우가 시작점)
2. 한 줄 요약(워크플로우 전체를 한 문장으로 이해)
3. 히어로 비주얼(보조이며, 없어도 홈이 동작해야 함)
4. 헤더 도구(메가메뉴, 다크 모드)

## 섹션 (위 → 아래)

| # | 섹션 | 내용 | 글의 출처 |
|---|---|---|---|
| 0 | 공통 헤더 | 사이트 이름(홈 링크), 가이드 버튼 3개와 메가메뉴, 다크 모드 토글. 768px 미만은 햄버거 메뉴 | siteConfig |
| 1 | 히어로 | 사이트 이름(h1), 한 줄 요약, 비주얼 | 요약은 최종 md 원문 |
| 2a | 강조 카드: 최종 워크플로우 | 메뉴 이름, "이 문서는 순서 · 스킬 · 프롬프트만 다룹니다.", "0~10단계" | md·siteConfig |
| 2b | 보조 카드 2개 | 웹사이트 제작 순서(첫 문단, "10단계"), 디자인 스킬(첫 문단, "9단계") | md·siteConfig |

- 카드는 전체가 링크다. 한 번 누르면 해당 가이드로 간다.
- 단계까지 바로 가는 탭 두 번 경로는 헤더 메가메뉴가 맡는다(가이드 버튼 → 단계 버튼).
- 최종 카드는 md 첫 문단 대신 다음 문장을 쓴다. 첫 문단인 한 줄 요약이 히어로와 겹치기 때문이다.
- 단계 수는 메가메뉴 버튼 수가 아니라 작업 단계 수다.

## 배치 의도

- **375px**: 글 → 작은 비주얼 → 강조 카드 → 보조 카드 2개를 세로로 놓는다. 첫 화면에 강조 카드의 윗부분이 보여야 한다. 비주얼이 카드를 밀어내지 않는다.
- **768px**: 보조 카드 2개를 나란히 둔다.
- **1280px 이상**: 히어로는 글과 비주얼을 2단으로 놓는다. 카드는 강조 1개와 보조 2개의 크기 차이로 위계를 드러낸다.
- **모션**: 히어로 → 카드 순서로 한 번만 등장한다. `prefers-reduced-motion`이면 바로 표시한다.

## 상태와 범위

- 카드 제목과 링크는 설정에서 나오므로 항상 보인다.
- 비주얼이 없거나 실패하면 비주얼만 숨기고, 글이 그 자리를 채운다.
- 소개 문장은 자르지 않는다. 카드는 소개가 3줄쯤 되어도 깨지지 않아야 한다.
- JS가 꺼지면 brief의 noscript 안내와 md 원본 링크 3개를 보여 준다.

## 만들지 않을 것

- 검색창, "시작하기" 같은 중복 버튼, 통계·후기, 푸터, 문서에 없는 홍보 문구.
- 홈의 단계 바로가기 목록도 만들지 않는다. 용어집이 홈을 '소개와 입구만'으로 정의한다.

## 정하지 않은 것 (구현자가 지어내지 않는다)

- **시각 방향·비주얼 종류**: 4단계 대표 페이지에서 DESIGN.md를 잠근 뒤 적용한다.
- **카드 글의 출처**(5단계 스펙)
  - 실행할 때 md에서 읽으면: Skeleton이 필요하고, 실패하면 카드에서만 소개를 숨긴다.
  - siteConfig에 적어 두면: 같은 글이 md와 설정 두 곳에 생긴다.
- **단계 수 표기**: 설정에 직접 적을지, md에서 계산할지도 5단계에서 정한다. 계산한다면 코드 블록 안의 `#` 줄은 제목으로 세지 않는다. 실제로 `# 세션 시작`, `# 프로젝트명` 같은 가짜 제목이 있다.
